# 「我的小站」自动化测试工程

> **Playwright + pytest + Page Object 模式**，为一个 Flask 网站搭建的 UI 自动化测试工程。
> 28 条用例覆盖登录、内容发布、数据同步、界面兼容四大模块，测试数据自动清理，一键生成 HTML 报告。

被测对象是我自己开发的个人网站（Python + Flask + SQLite），
部署在 PythonAnywhere，包含登录鉴权、心理话发布、照片上传等功能。

---

## 一、为什么做这个项目

我此前对同一个网站做过一轮**手工测试**（79 条用例，发现 3 个缺陷，产出
[测试计划](../01-测试计划/测试计划.md)、[测试用例](../02-测试用例/测试用例.md)、
[缺陷报告](../03-缺陷报告/缺陷报告.md)）。

手工测试的问题是：**改一次代码就要重新点一整天**。

所以我把其中**可重复执行的核心用例**自动化了 —— 现在
**30 秒**就能跑完全部 28 条，而且跑完自动清理测试数据、自动生成报告。

---

## 二、技术选型

| 技术 | 用途 | 为什么选它 |
|---|---|---|
| **Playwright** | 浏览器自动化 | 自动等待元素、支持多浏览器、能录 trace 回放；比 Selenium 上手简单得多 |
| **pytest** | 测试框架 | fixture 机制强大（登录态复用、自动清理都靠它）、生态成熟 |
| **pytest-playwright** | 官方插件 | 提供 browser / context / page 夹具，与 pytest 无缝集成 |
| **pytest-html** | 测试报告 | 生成单文件 HTML 报告，发给别人不用附带资源目录 |
| **python-dotenv** | 配置管理 | 密码从 `.env` 读，代码里零明文 |

## 三、目录结构

```
自动化测试/
├── config.py              # 配置：网站地址、密码（从 .env 读）、测试数据前缀
├── conftest.py            # 全局夹具：登录态复用、测试数据清理、失败自动截图
├── pytest.ini             # pytest 配置（报告路径、用例命名规则）
├── requirements.txt
├── .env.example           # 配置模板（真 .env 被 gitignore 忽略）
│
├── pages/                 # ★ Page Object 层：页面元素和操作都封装在这里
│   ├── base_page.py       #   基类：导航栏、flash 提示、横向溢出检测
│   ├── login_page.py
│   ├── home_page.py
│   ├── thoughts_page.py
│   ├── photos_page.py
│   └── admin_page.py
│
├── tests/                 # ★ 测试用例层：只写业务语言，不出现裸选择器
│   ├── test_login.py
│   ├── test_publish.py
│   ├── test_photos.py
│   ├── test_data_sync.py
│   └── test_ui.py
│
└── tools/
    └── 清理测试数据.py      # 兜底清理脚本（自动清理失效时手动跑）
```

**分层的好处**：页面改版时只需要改 `pages/`，`tests/` 里的用例一行都不用动。

## 四、设计要点

### 1. Page Object 模式
选择器全部集中封装在 `pages/` 里，测试用例里写的是
`登录页.登录(密码, "男方")` 这种业务语言，而不是一堆 CSS 选择器。

### 2. 登录态会话复用
`conftest.py` 里的 `auth_state` 夹具**真登录一次**，用 `storage_state()` 保存会话，
其余 27 条用例直接复用 —— 省掉每条用例重复登录的开销。
（Flask 的 session cookie 是签名过的，没法手写伪造，只能先真登录一次。）

### 3. 测试数据自动清理
这是本项目最看重的一点：**自动化测试会往真实网站写数据，不能让网站变脏。**

- 所有测试创建的内容都带统一前缀 `【自动化测试】xxxxxx`
- `admin` 夹具用 `yield` 实现 teardown —— **即使用例中途失败，清理代码照样执行**
- 断言只针对带前缀的数据，不受网站已有真实内容影响
- 另提供 `tools/清理测试数据.py` 兜底（测试被 Ctrl+C 强杀时用）

跑完后网站「心理话」和「照片」页面不会留下任何测试垃圾。

### 4. 用 xfail 把已知缺陷变成「活的回归测试」
网站有 2 个未修复的缺陷，对应的用例断言按**正确行为**写，用
`@pytest.mark.xfail(strict=True)` 标记为「预期失败」：

| 用例 | 对应缺陷 | 当前状态 |
|---|---|---|
| `test_tc_home_01_long_text_no_horizontal_overflow` | BUG-001 超长字符撑破排版 | XFAIL（复现） |
| `test_tc_sync_05_double_click_should_not_duplicate` | BUG-003 重复提交写入重复数据 | XFAIL（复现） |

`strict=True` 的意思是：**哪天后端把缺陷修好了，这条用例会通过，pytest 会报
`XPASS(strict)` 失败**，提醒你「缺陷已修复，请回来更新缺陷报告」。
这样 xfail 用例就不是写死的档案，而是能跟着代码变化的活测试。

### 5. 敏感信息不落代码库
网站密码写在 `.env` 里，`.env` 被 `.gitignore` 忽略。
仓库里只有 `.env.example` 模板，别人 clone 下来填上自己的密码就能跑。

### 6. 把「排版好不好看」变成可断言的指标
BUG-001（超长字符撑破页面）传统上只能靠眼睛看。这里用 JS 量化：

```python
document.documentElement.scrollWidth > document.documentElement.clientWidth
```

页面出现横向滚动条 = 排版溢出。**主观判断变成了客观断言。**

### 7. 故意不测「修改密码」功能
后台有一个 `POST /admin/password` 表单，提交它会**真实改写服务器上的密码**。
**本项目有意不覆盖这个功能**，以免把真实密码改掉。
（这是有意识的风险规避，不是遗漏。）

## 七、怎么运行

### 1. 准备环境

```bash
pip install -r requirements.txt
playwright install chromium
```

> 如果 pip 用的是国内镜像源，可能没有 playwright，请加 `-i https://pypi.org/simple`。

### 2. 配置被测网站

```bash
cp .env.example .env
```

编辑 `.env`：

```ini
# 本地测试（推荐，跑得快、可反复跑）
BASE_URL=http://127.0.0.1:5000
SITE_PASSWORD=你的网站密码
```

> 测试本地网站前，先启动它。

### 3. 跑测试

```bash
python -m pytest                 # 全量跑 + 生成报告
python -m pytest --headed        # 打开浏览器窗口，看它自己操作
python -m pytest tests/test_login.py -v    # 只跑登录模块
```

### 4. 兜底清理（一般用不到）

```bash
python tools/清理测试数据.py
```

## 八、踩过的坑（都是真踩过的）

写这个工程的过程中，下面这几件事都实实在在卡住过我，记录下来备查：

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **用字是「心*理*话」** | 代码里全写的是「心理话」不是「心里话」，选择器用错字永远匹配不到，还不报错 | 选择器统一用「心理话」 |
| 2 | **删除按钮有 `confirm()` 弹窗** | Playwright **默认自动点「取消」**，结果表单根本不提交，而且不报错 —— 删除测试「删不掉却也不失败」 | `page.on("dialog", lambda d: d.accept())` |
| 3 | **后台表单的 input 没有 id** | 4 个表单的输入框都没 id，直接按 name 定位会撞车 | 用 `form[action="/admin/post"]` 限定作用域 |
| 4 | **flash 消息是一次性的** | 刷新页面提示就没了，断言写晚了永远失败 | 铁律：**先断言提示，再跳转页面** |
| 5 | **Playwright 连点复现不了 BUG-003** | 连点 3 次只写入 1 条 —— 第一次点击后页面立刻开始跳转，后两次被浏览器丢掉 | 改成**在页面里用 fetch 并发发 3 个请求**，走同一接口同一会话，稳定复现 3 条 |
| 6 | **后台照片列表不显示说明文字** | `.manage-photo` 里只有缩略图，没法按 caption 文字定位删除 | 先去前台相册（有说明文字）拿到 `img[src]`，再回后台按地址精确定位 |
| 7 | **登录态缓存会让登录用例失效** | 带登录态的 page 访问 `/login` 会被自动跳回主页 | 登录用例一律用独立的**未登录** context |
| 8 | **`created_at` 只精确到分钟** | 同一分钟内的重复记录时间戳完全一样，没法靠时间区分 | 判重复只能数 `.post-card` **数量** |
